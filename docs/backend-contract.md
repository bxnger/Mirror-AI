# Backend contract — PROPOSAL (not confirmed)

Status: **draft from frontend, needs confirmation from Erasyl.** Nothing below exists yet.
The frontend currently runs entirely on `src/lib/api/demo-adapter.ts` (local rules, no network).

Canonical shapes are the TypeScript types in `src/domain/types.ts`. The JSON should match them 1:1 so that no mapping layer is needed.

## Open questions for Erasyl
1. Base URL and environments (local / staging / prod). CORS for the Vercel domain?
2. Auth for the MVP: anonymous device id, magic link, or none? (The frontend currently has no users.)
3. Are profile, decision and plan stored server-side, or is the backend stateless (send profile → get analysis)?
4. LLM latency budget. Should `/compare` stream, or is a 5–15 s request OK with a loading state?
5. Error format. Proposed: `{ "error": { "code": string, "message": string } }` + HTTP status.
6. Language: does the LLM answer in Russian when `locale: "ru"` is passed?

## Proposed endpoints
| Method | Path | Body | Response |
|---|---|---|---|
| POST | `/api/compare` | `{ profile: Profile, decision: Decision, locale: "ru" }` | `Comparison` (with `source: "ai"`) |
| POST | `/api/plan` | `{ profile, decision, pathId: "A" \| "B", locale }` | `Plan` |
| PUT | `/api/profile` | `Profile` | `Profile` (only if server-side storage, see Q3) |
| PATCH | `/api/plan/:id/tasks/:taskId` | `{ done: boolean }` | `PlanTask` (only if server-side storage) |

### Comparison rules the AI response must respect
- `risks[].code` comes from the `RiskCode` union. If the LLM needs free-text risks, we add `{ code: "custom", text: string }` together.
- `uncertainty` is low / medium / high with `uncertaintyReasons`. **No probability of success, no salary or outcome predictions.**
- Load and total-hours numbers should be computed deterministically (the same formulas as `src/domain/analysis.ts`), not generated by the LLM.
